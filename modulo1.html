Fundamentos de Backend, Testing y Datos

Estructura de proyectos, web scraping, testing, SQL y formatos de datos: las bases con las que arranca cualquier flujo de trabajo en Python.

A Estructura y entornos de proyecto

Estructura de carpetas estándar en proyectos Python

Un proyecto Python "serio" separa el código fuente, las pruebas, la configuración y la documentación en carpetas predecibles. Esto no es estética: cualquier herramienta (pytest, un linter, un CI/CD) espera encontrar las cosas en lugares convencionales para poder automatizarse sin configuración extra.

Separar src/ de tests/ evita importar accidentalmente código de prueba en producción, y facilita empaquetar el proyecto para distribuirlo (por ejemplo con pip).

Entornos virtuales a fondo

venv · virtualenv · conda

Un entorno virtual aísla las dependencias de un proyecto para que no choquen con las de otro (por ejemplo, un proyecto que necesita pandas 1.5 y otro que necesita pandas 2.0 en la misma máquina).

HerramientaQué esCuándo usarla
venvMódulo incluido en Python 3 desde la instalación estándar.Proyectos Python puros, sin dependencias fuera del ecosistema pip.
virtualenvHerramienta previa a venv, más rápida y con más opciones de compatibilidad entre versiones de Python.Cuando necesitas soporte para versiones muy antiguas de Python o funciones que venv no cubre.
condaGestor de entornos y de paquetes a la vez; puede instalar también binarios no-Python (como CUDA o librerías de C).Data Science / ML donde se necesitan paquetes compilados (numpy, GPU, etc.) sin compilarlos a mano.

requirements.txt y gestión de dependencias

Es la "receta" de un proyecto: la lista exacta de paquetes (y versiones) que hay que instalar para que el código funcione igual en cualquier máquina. Se genera con pip freeze > requirements.txt y se instala con pip install -r requirements.txt.

Fijar versiones exactas (pandas==2.1.0) evita el clásico "en mi máquina funciona": sin eso, cada instalación nueva puede traer versiones distintas y romper el código silenciosamente.

B Web scraping y APIs

Introducción a BeautifulSoup: selectores CSS

BeautifulSoup convierte el HTML de una página en un árbol navegable de objetos Python. Los selectores CSS (los mismos que usarías en una hoja de estilos) permiten apuntar directo al dato que quieres extraer sin recorrer el árbol manualmente.

soup.select("div.precio > span")   # todos los <span> hijos directos de div.precio
soup.select_one("#titulo")         # el primer elemento con id="titulo"

Verbos HTTP (GET, POST, PUT, DELETE)

Cada verbo comunica una intención distinta al servidor sobre qué hacer con un recurso. Usar el verbo correcto no es solo convención: muchos frameworks y cachés se comportan distinto según el verbo (por ejemplo, GET se puede cachear, POST no).

GET → leerPOST → crear PUT → reemplazarDELETE → eliminar

Cabeceras HTTP (Headers)

User-Agents · Cookies · Auth Tokens

Las cabeceras viajan junto a cada request/response y llevan metadatos: quién hace la petición (User-Agent), qué sesión mantiene (Cookie) o con qué credenciales se autentica (Authorization: Bearer <token>). Muchos scrapers fallan simplemente por no enviar un User-Agent creíble.

Librería Requests vs urllib

urllib

Incluida en la librería estándar de Python. Más verbosa: manejar JSON, cookies o reintentos requiere más código propio.

requests

Librería de terceros con una API mucho más simple y humana (requests.get(url).json()). Es el estándar de facto en la comunidad para hacer HTTP en Python.

Estrategias de reintento y backoff exponencial

Cuando una petición falla (por ejemplo, el servidor está saturado), reintentar de inmediato y en bucle solo empeora las cosas. El backoff exponencial espera cada vez más tiempo entre reintentos (1s, 2s, 4s, 8s…), dándole al servidor tiempo real de recuperarse.

Mocking de APIs externas

unittest.mock · respx

Al probar código que llama a una API externa, no quieres depender de que esa API esté disponible (ni pagar por cada llamada de test). El "mocking" reemplaza la llamada real por una respuesta falsa controlada, para poder probar la lógica propia de forma rápida, aislada y reproducible.

Herramientas de prueba: Postman / Insomnia

Clientes gráficos para construir y disparar peticiones HTTP a mano (con headers, body, auth) sin escribir código. Útiles para explorar una API antes de integrarla, o para documentar y compartir colecciones de endpoints con el equipo.

C Testing

Decoradores: el concepto de "envolver" funciones

Un decorador es una función que recibe otra función y devuelve una versión "envuelta" de ella, añadiendo comportamiento extra (logging, medir tiempo, requerir autenticación) sin tocar el código original.

En Python, @nombre encima de una función es solo azúcar sintáctico para funcion = nombre(funcion).

Pytest Fixtures

Son funciones reutilizables que preparan datos o recursos de prueba (una conexión a base de datos falsa, un usuario de ejemplo, un DataFrame) para que varios tests los reciban listos, sin repetir la misma configuración en cada uno.

Midiendo la cobertura: pytest-cov

La cobertura mide qué porcentaje de las líneas de código realmente se ejecutan durante los tests. Un número alto no garantiza que los tests sean buenos, pero un número bajo sí es una señal clara de partes del código que nunca se validan.

D SQL y bases de datos

Sintaxis SQL básica (SELECT, WHERE…)

SELECT nombre, edad
FROM clientes
WHERE pais = 'España'
ORDER BY edad DESC;

SELECT elige columnas, FROM elige la tabla, WHERE filtra filas antes de agrupar u ordenar.

Tipos de JOINs

Un JOIN combina filas de dos tablas según una condición de coincidencia. La diferencia entre tipos está en qué hacer con las filas que no encuentran pareja.

SQL Window Functions

RANK · LEAD · LAG

Calculan un valor "sobre una ventana" de filas relacionadas sin colapsar el resultado en una sola fila por grupo (a diferencia de GROUP BY). Sirven para rankings, comparar una fila con la anterior/siguiente, o acumulados.

SELECT nombre, ventas,
  RANK() OVER (ORDER BY ventas DESC) AS puesto,
  LAG(ventas) OVER (ORDER BY fecha) AS ventas_dia_anterior
FROM reporte;

Conexión Python-SQL (SQLAlchemy básico)

SQLAlchemy permite hablarle a una base de datos SQL desde Python, ya sea escribiendo SQL directo o usando su ORM (mapear tablas a clases Python) para no escribir SQL a mano en cada consulta.

E Datos y formatos

JSON vs XML vs YAML

JSON

Ligero, nativo de JavaScript, el estándar para APIs REST. Sin comentarios, sintaxis estricta de llaves y comas.

XML

Más verboso, con etiquetas de apertura/cierre. Sigue usándose en sistemas empresariales y configuraciones antiguas (SOAP, algunos formatos de Office).

YAML

Basado en indentación, muy legible para humanos. Es el formato típico de archivos de configuración (Docker Compose, CI/CD, Kubernetes).

Loc vs iLoc: cómo filtrar datos

Selecciona porEjemplo
.locEtiqueta/nombre del índice o columnadf.loc[3, 'edad']
.ilocPosición numérica (como una lista)df.iloc[0, 2]

Confundirlos es una fuente clásica de bugs silenciosos cuando el índice del DataFrame no coincide con la posición (por ejemplo, después de un filtro).

Generación de datos falsos con Faker

La librería Faker genera datos ficticios pero realistas (nombres, direcciones, correos, fechas) para poblar bases de datos de prueba o anonimizar ejemplos, sin usar información real de personas.
